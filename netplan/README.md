# נט־פלאן: תכנון, תיעוד וניטור רשתות תקשורת

באוויר (אחרי מיזוג ל-main): https://devopsdevopshaim-wq.github.io/devops-hub/netplan/

מגדירים אתר, מבנים, קומות וחדרים בכל קומה. המערכת בונה תכנית תקשורת מלאה: ארונות תקשורת, מתגים, VLAN-ים, כתובת IP לכל שקע בכל חדר, הגדרות מוכנות לציוד, ניטור צריכת נתונים, סטטיסטיקות ותכנית להדפסה.

## מסכים

| מסך | מה יש בו |
| --- | --- |
| סקירה | נתוני מפתח, אזהרות (PoE, עומס קישורים, חבילת אינטרנט), המלצה מה לשים בארון (Hub / מתג / נתב / חומת אש), רשימת ציוד לרכישה וכתובות שירותי הליבה. |
| הגדרת המבנה | תבניות מוכנות (ארון אחד ל-40 חדרים, בניין 8×35, מלון, קמפוס, בית ספר), מבנים וקומות, נקודות קצה בחדר, תשתית, טווח כתובות, רשת לכל קומה או רשת מבודדת לכל חדר, ו-IPv6. כל שינוי מעדכן את כל התכנית מיד. |
| שרטוט הרשת | שרטוט אנכי של הבניין עם כל ארון קומה, סיבים, ליבה, חומת אש וספקים, ושרטוט לוגי לכל ארון. אפשר להוריד כ-SVG. |
| ארונות ומתגים | חזית ארון לכל IDF ול-MDF, מפת פורטים של כל מתג (לחיצה מציגה שקע, חדר, VLAN ו-IP) וטבלת חיווט. |
| רשתות ו-VLAN | כל הרשתות: VLAN, מסכה, Gateway, טווח DHCP, ניצול ו-IPv6. אפשר לייצא ל-CSV. |
| כתובות לפי חדר | לכל שקע: לוח ניתוב, פורט במתג, VLAN, ‏IP, מסכה ו-Gateway. כרטיס חדר עם כל ההגדרות, שאפשר גם להדפיס. |
| הגדרות לציוד | קובצי Cisco IOS-XE לליבה (StackWise Virtual), להפצה (OSPF) ולכל מחסנית מתגי קומה, וקובץ ISC Kea DHCPv4 עם שמירת כתובת לכל שקע לפי Option 82. |
| ניטור תעבורה | סקופ בזמן אמת לקו הראשי, לליבה, לכל ארון, לחדר או לכתובת. מציג קבלה ושליחה, ממוצע, שיא, אחוזון 95 ונפח מצטבר, יחד עם הצרכנים הגדולים, עומס הקישורים ומפת חום לפי חדרים. |
| סטטיסטיקות | ניצול פורטים, כתובות ו-PoE, תעבורת שיא לכל ארון ונתונים חיים. |
| מדריך | השוואה בין Hub, מתג, נתב וחומת אש, שיטת המספור, דוגמת 40 החדרים וסדר ההטמעה. |

## שיטת התכנון

- **כתובות:** ‏`10.0.x.x` לשירותי ליבה, `10.1.x.x` למבנה הראשון, `10.2.x.x` לשני וכן הלאה. כשהטווח קטן מ-‎/16 למבנה, הכתובות מוקצות ברצף (VLSM).
- **VLAN:** ‏`1BFF` מחשבים, `2BFF` טלפוניה (B = מבנה, FF = קומה), ו-`3Bkk` לשירותי המבנה (10 Wi-Fi, ‏20 אורחים, 30 מצלמות, 40 IoT, ‏50 מדפסות, 99 ניהול). במצב "רשת לכל חדר", החדרים מקבלים VLAN-ים 1000–1999.
- **גודל רשת:** מחושב מכמות המכשירים, ועליה אחוז הצמיחה שמגדירים ועשר כתובות לציוד קבוע.
- **ארונות:** ארון נוסף בקומה בכל פעם שמספר החדרים עובר את המקסימום לארון (ברירת מחדל 40, לפי מגבלת 90 מ׳ של TIA-568). מספר המתגים מחושב מכמות השקעים ועליה אחוז הפורטים הרזרביים.
- **PoE ועומסים:** תקציב לפי מחלקת PoE של כל מכשיר (טלפון, מצלמה, נקודת גישה לפי דור ה-Wi-Fi). עומס השיא מחושב לכל ארון ומושווה לקישור Uplink יחיד, כלומר למצב שבו אחד הקישורים נפל.

## נתונים אמיתיים בניטור

בלי מקור נתונים, הניטור מציג סימולציה שמסומנת ככזו. לחיבור נתונים אמיתיים צריך אסף נתונים (Telegraf, ‏n8n, ‏Prometheus) שמפרסם JSON עם CORS:

```json
{ "items": [ { "ip": "10.1.11.10", "rx_bps": 18500000, "tx_bps": 2100000 }, { "ip": "WAN", "rx_bps": 912000000, "tx_bps": 210000000 } ] }
```

אפשר גם לייבא קובץ CSV עם העמודות `ip,rx_bps,tx_bps`.

## הרצה ובדיקות

אתר סטטי בלי שלב בנייה:

```bash
cd netplan
python3 -m http.server 8080   # http://localhost:8080
npm test                      # בדיקות למנוע התכנון ולמחולל ההגדרות
```

התכנית נשמרת בדפדפן (localStorage). אפשר לשמור ולטעון אותה כקובץ JSON.

לפני הטמעה בשטח, מהנדס רשתות צריך לבדוק את ההגדרות ולהחליף כל ערך `<CHANGE-ME>` (סיסמאות ומפתחות).
