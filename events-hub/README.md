# רגעים: מערכת לאירועים

אפליקציה לאירועים. בזמן האירוע אורחים שולחים תמונות להדפסה דרך QR, ואחרי האירוע האפליקציה נשארת בטלפון שלהם כחנות מתנות ומוצרים.

**הכול ב-GitHub:**
- **אפליקציית הלקוח:** https://devopsdevopshaim-wq.github.io/devops-hub/events-hub/
- **אפליקציית הניהול:** https://devopsdevopshaim-wq.github.io/devops-hub/events-hub/admin/
- **הקוד:** התיקייה `events-hub/` בריפו `devops-hub`.

כל מיזוג ל-main מעדכן את האפליקציה לבד.

## שתי אפליקציות: מנהל ולקוח

| | אפליקציית הלקוח | אפליקציית הניהול |
|---|---|---|
| כתובת | `events-hub/` (ודף האורח `event.html?c=<קוד>` מה-QR) | `events-hub/admin/` |
| למי | אורחים ולקוחות | בעל העסק בלבד (סיסמה) |
| התקנה בטלפון | "📲 התקנה" או בדפדפן: "הוספה למסך הבית" | כפתור "📲 התקנה", או "עוד ← התקנת אפליקציית הניהול" |
| אייקון | ורוד | כהה עם כוכב זהב |
| ניווט | סרגל תחתון: חנות · האירועים שלי · הזמנות · סל | סרגל תחתון: בקרה · אירועים · הזמנות · ספקים · עוד |

**התקנה אוטומטית אחרי סריקת QR:** כשאורח סורק את ה-QR, מופיע מיד פס "📲 שמרו את האפליקציה בטלפון". אחרי ההרשמה חלון ההתקנה נפתח לבד, פעם אחת. באנדרואיד (Chrome) ההתקנה היא לחיצה אחת. באייפון, בסמסונג או כשהקישור נפתח בתוך וואטסאפ, החלון מציג את השלבים המדויקים לאותו טלפון. אף דפדפן לא מתקין בלי לחיצה אחת של המשתמש, ולכן זה הכי אוטומטי שאפשר.

**חיבור ל-QR של פריים מגנטים (frame-studio):** דף האורחים של frame-studio (`live.html`) מותקן גם הוא כאפליקציה. כדי שיופיע בו כפתור 🛍️ לחנות של רגעים, כתובת האפליקציה כתובה בקובץ `frame-studio/guest-app.json`, בשדה `storeUrl`, וכבר מוגדרת.

שתי האפליקציות עובדות מול אותו שרת, אבל כל אחת מותקנת בנפרד ומופיעה עם אייקון משלה במסך הבית. בהתקנה שתיהן נפתחות במסך מלא, בלי שורת כתובת.

## מה יש במערכת

### באירוע (דרך QR)
- **מנהל יוצר אירוע** ומגדיר כמות תמונות לכל אורח, מגבלה כוללת (אופציונלי) ו**עד 3 אפשרויות הדפסה**: מגנט, בלוק עץ או מסגרת קרטון, כל אחת בגודל לבחירה.
- לכל אירוע נוצר **QR** (אפשר להוריד כ-PNG) שמוביל לדף האורח.
- **האורח**: נרשם עם שם וטלפון, בוחר סוג הדפסה, מצלם או בוחר תמונה, עורך אותה ושולח להדפסה. מונה התמונות שנותרו נאכף בשרת.
- **עורך תמונות**:
  - חיתוך אוטומטי ליחס הגודל של ההדפסה, זום, הזזה וסיבוב
  - בהירות, ניגודיות ורוויה, ו-8 פילטרים
  - **אפקטים חכמים (AI)**: שיפור אוטומטי, קריקטורה, ציור עיפרון, פופ-ארט, ציור שמן, והסרת רקע (דרך remove.bg, צריך מפתח API)
  - טקסט וברכות, מדבקות שאפשר לגרור, ו-6 מסגרות
  - **אנימציות**: זום, פעימה, גשם לבבות, קונפטי, נצנוצים ושלג. נוצר סרטון קצר שנשמר בטלפון ובגלריה האישית. הסרטון לא נספר במכסת ההדפסה.
- המנהל רואה את כל התמונות של כל אירוע עם סטטוס הדפסה: ממתין, בהדפסה, הודפס, נמסר.

### אחרי האירוע: האפליקציה נשארת בטלפון
- האתר הוא **PWA**, כלומר אפשר להתקין אותו למסך הבית ("📲 התקנת האפליקציה").
- בלשונית "האירועים שלי" הלקוח רואה את התמונות מכל האירועים שבהם סרק QR.
- **חנות**: מגנטים, בלוקים, מסגרות, תמונות בעיצוב מיוחד, חבילות (חינה, חתונה, מקווה, בר/בת מצווה, ברית, יום הולדת), מתנות, מתוקים, פרחים ועיצוב.
- למוצרים שצריכים תמונה הלקוח בוחר תמונה מהאירוע או מעלה תמונה חדשה.
- **קולקציות עונתיות**: חגים, כנסים וחבילות מיוחדות, עם תאריכי התחלה וסיום. מוצרים שמשויכים לקולקציה מוצגים בחנות רק בזמן שלה.
- **מעקב הזמנה** ללקוח עם ציר זמן.

### אפליקציית הניהול (`/admin/`)
- **ספקים**: לשונית לכל תחום (מגנטים, בלוקים, מסגרות, מתנות, מתוקים, פרחים…). לכל ספק נשמרים הערים והאזורים שהוא משרת.
- **שליחים**: רשימה לפי עיר, סינון "מי משרת את העיר X", ודוח כיסוי לפי אזור שמראה אילו ערים בלי שליח.
- **ערים**: כ-75 ערים מחולקות ל-5 אזורים. אפשר להוסיף ערים.
- **שיוך אוטומטי**: כשמגיעה הזמנה, למשל מבאר שבע, המערכת משייכת **ספק מבאר שבע** בתחום של כל מוצר ו**שליח מבאר שבע**. אם אין אף אחד בעיר, היא בוחרת ספק או שליח מאותו אזור (דרום). מתוך המתאימים נבחר מי שיש לו הכי פחות הזמנות פתוחות. אם לא נמצא אף אחד, ההזמנה מסומנת "דורשת שיוך ידני". אפשר גם לשייך ידנית.
- **סטטוס משלוח עם זמנים**: שולם → נשלח לספק → בהכנה → מוכן → נאסף ע"י שליח → בדרך → נמסר (או בעיה/עיכוב). כל שינוי נרשם עם תאריך ושעה.
- **משלוחים תקועים**: לכל שלב מגדירים זמן יעד בשעות. הזמנה שעברה אותו מסומנת באדום ⚠️. אפשר להוסיף **הערות**, פנימיות או גלויות ללקוח.
- לוח בקרה: הזמנות פתוחות, משלוחים תקועים, תמונות שממתינות להדפסה, והכנסות.

### סליקה
- **התשתית מוכנה**. הלקוח מועבר ל**דף תשלום מאובטח של חברת הסליקה**, כך שפרטי האשראי לא עוברים בשרת ולא נשמרים בו. אחרי התשלום חברת הסליקה מעדכנת את השרת (webhook).
- המחיר תמיד מחושב בשרת, ולא לפי מה שהדפדפן שולח.
- כרגע פועל **מצב בדיקה (mock)**, בלי חיוב אמיתי.
- יש שלד מוכן ל-4 חברות סליקה ישראליות: **טרנזילה, קארדקום, Grow (משולם), PayPlus**.
- **קיצור דרך לחברת הסליקה**:
  - בממשק הניהול יש כפתור "💳 כניסה לחברת הסליקה" בראש המסך, ובלשונית "סליקה והגדרות" יש קישורי הרשמה וכניסה לכל חברה.
  - בתיקייה `shortcuts/` יש קובצי קיצור דרך (‎.url) שאפשר להעתיק לשולחן העבודה.

| חברה | אתר |

| קארדקום | https://www.cardcom.solutions/ |

> כדאי לוודא את כתובות ממשקי הניהול מול חברת הסליקה אחרי פתיחת החשבון. אפשר לשנות את כתובת הכפתור בהגדרות.

## איך זה בנוי: GitHub Pages + שרת קטן ב-Cloudflare

GitHub Pages מגיש רק דפים, ולא מריץ שרת. האפליקציה צריכה שרת בשביל כמה דברים:
- שהתמונות של האורחים יגיעו אליך
- שהזמנות יישמרו
- שתשלומים יאושרו

לכן העבודה מחולקת לשניים:

| חלק | איפה | מאיפה מתעדכן |
|---|---|---|
| האתר (שתי האפליקציות) | GitHub Pages: `devops-hub/events-hub/` | `vacation-hub-pages.yml`, בכל שינוי ב-`events-hub/public/` |
| השרת (נתונים, תמונות, הזמנות, סליקה) | Cloudflare Workers: `regaim-events.devopsdevopshaim.workers.dev` | `events-hub-deploy.yml`, בכל שינוי ב-`events-hub/src/` |

- **שרת נפרד:** השרת של רגעים נפרד משרת הכניסה (`spider-auth`), כך ששינוי כאן לא יכול לפגוע בו. שניהם רצים באותו חשבון Cloudflare חינמי ונפרסים עם אותו טוקן.
- **איפה נשמרים הנתונים:** ב-Durable Object עם SQLite: רשומות, ותמונות עד 2MB כל אחת. הטלפון מקטין את התמונות לפני השליחה.
- **התחברות מנהל:** אסימון חתום שנשמר באפליקציית הניהול בטלפון, ל-30 יום.

### הקמה, פעם אחת
1. ב-GitHub נכנסים ל-Settings ← Secrets and variables ← Actions, ומוסיפים את **`EVENTS_ADMIN_PASSWORD`**. זו הסיסמה לאפליקציית הניהול, כדאי לפחות 10 תווים.
2. ב-Actions בוחרים **Deploy Regaim (events-hub) server to Cloudflare** ← Run workflow. מעכשיו זה קורה לבד בכל שינוי.
3. נכנסים לאפליקציית הניהול עם הסיסמה, ומתקינים אותה בטלפון.

אם אין טוקן Cloudflare בריפו, ה-workflow מודיע על כך ולא פורס. השרת של רגעים משתמש באותו טוקן של שרת הכניסה (`CLOUDFLARE_API_TOKEN`, או הסוד `CLOUDFLARE`).

### סודות אפשריים
כולם ב-GitHub Actions secrets. ה-workflow מעביר אותם ל-Cloudflare.

| סוד | מה זה |
|---|---|
| `EVENTS_ADMIN_PASSWORD` | סיסמת אפליקציית הניהול (חובה) |
| `EVENTS_REMOVE_BG_API_KEY` | הסרת רקע בעורך (remove.bg) |
| `EVENTS_PAYMENT_PROVIDER` | `tranzila` / `cardcom` / `grow` / `payplus`. בלי הסוד הזה המערכת במצב בדיקה |
| `EVENTS_PAYMENT_TERMINAL`, `EVENTS_PAYMENT_API_KEY`, `EVENTS_PAYMENT_API_SECRET` | פרטי המסוף מחברת הסליקה |

## חיבור חברת סליקה (כשתהיו מוכנים)
1. פותחים חשבון סוחר אצל אחת החברות. הקישורים בטבלה למעלה.
2. מוסיפים ב-GitHub את הסודות `EVENTS_PAYMENT_PROVIDER` ופרטי המסוף.
3. בקובץ `src/payments/index.js` משלימים שתי פונקציות לפי התיעוד של החברה:
   - `createPayment`: יוצרת דף תשלום ומחזירה כתובת להפניה
   - `parseCallback`: מפענחת את עדכון ה-webhook
4. בממשק של חברת הסליקה מגדירים כתובת עדכון: `https://regaim-events.devopsdevopshaim.workers.dev/api/payments/callback`.

## הרצה במחשב (פיתוח ובדיקות)
```bash
cd events-hub
npm install
npm start            # http://localhost:3000  ניהול: /admin/  (סיסמה מקומית: admin123, או ADMIN_PASSWORD בקובץ .env)
npm test             # בדיקות השרת
npm run worker:dev   # אותו שרת בסימולטור של Cloudflare (צריך קובץ .dev.vars עם ADMIN_PASSWORD=...)
```
- במחשב, השרת והאתר רצים מאותה כתובת והנתונים נשמרים ב-`data/`.
- אותו קוד שרת (`src/app.js`) רץ גם ב-Cloudflare.
- כדי לבדוק את האתר מול שרת אחר, מוסיפים לכתובת `?api=https://...`.

המערכת מגיעה עם נתוני דוגמה: ערים, קטגוריות, מוצרים, קולקציות, וספקים ושליחים לדוגמה (מסומנים "(דוגמה)"). צריך להחליף אותם בפרטים אמיתיים באפליקציית הניהול.

```
src/auth.js            כניסת מנהל (אסימון חתום)

src/routing.js         שיוך ספק ושליח לפי עיר/אזור

src/payments/          תשתית סליקה + רשימת חברות וקישורים
server.js              הרצה במחשב

test/                  בדיקות: api.test.js (שרת), worker-smoke.mjs (מול Cloudflare)
```
